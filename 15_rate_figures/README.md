# 15 — Arrival-rate figures: shared setup

Setup for the four new figures vs. request arrival rate: secure completion,
security-triggered termination, mean end-to-end delay, and security-profile changes.
All five methods (RASP-Fog, SA-FF, RASP-Profile, RASP-Reloc, Static-Strong) run on
`../rasp_nsfnet.py` unchanged. The figure scripts are not written yet; this folder
only fixes the settings, the traces and the sweep.

```bash
python3 15_rate_figures/make_traces.py   # 25 seeds, ~5 s, writes traces/ and config.json
python3 15_rate_figures/pilot.py         # saturation pilot, 8 seeds, a few minutes
```

## Files

| File | Content |
|---|---|
| `exp_config.py` | The one shared config: run settings, threat, methods, rates, seeds, t-values, trace loader, `run(method, seed, rate)` |
| `make_traces.py` | Pre-generates one trace file per seed and writes `config.json` |
| `config.json` | Every run and model setting (parameter-table source) |
| `traces/seed_NNN.json.gz` | Request and threat trace per seed (~1.3 MB each, git-ignored; regenerated byte-for-byte by `make_traces.py`) |
| `pilot.py`, `pilot_raw.csv`, `pilot_summary.csv` | Saturation pilot |

## Settings

- NSFNET model as in `13_final_figures` (14 nodes, 21 links, cloud behind nodes 6 and 9, λ_D = λ_O = 0.5, τ_H = 8 s, incumbents protected).
- 300 s of Poisson arrivals, 60 s warm-up excluded, sessions run to completion, 1 s adaptation epoch.
- Dynamic threat: an independent walk per region (West, Central, East) over levels 1–3, one step every 5 s, p_up = p_down = 0.3. The long-run level is uniform over 1–3 (mean 2), the dynamic version of the fixed θ = 2 in `13_final_figures` Fig. 1. Rises force mandatory upgrades that need extra CPU, memory and bandwidth on loaded nodes (the resource contention). Falls allow downgrades after τ_H.

## Identical traces across methods

Each seed has one master Poisson trace at 64 req/s, with a thinning mark u ~ U(0,1) per request, plus one threat trace. The trace for rate r keeps the requests with u < r/64. Every method at every rate replays the same file. Lower-rate traces are subsets of higher-rate ones, so curves move smoothly with load. Random streams: arrivals `Random(seed)`, marks `Random(5000 + seed)`, threat `Random(1000 + seed)`.

## Pilot result (8 seeds)

Saturation starts at **18 req/s**: fog CPU is 83%, and rejection first appears (0.2–1.0%). By 20 req/s rejection is 1.3–3.4% and fog CPU 88%. Fog CPU plateaus at about 92–93% from 28 req/s on, and the extra load is rejected. No admitted request missed its deadline (`sla_miss_pct` = 0 everywhere).

## Sweep and seeds

- Rates (req/s): 4, 8, 12, 14, 16, then every 1 req/s from 17 to 24, then 26, 28, 32, 40, 48. That gives 18 points, with 9 of them in the 16–24 knee.
- 25 seeds (1–25), t(0.975, 24) = 2.064. Projected 95% half-widths, worst point: secure completion ±0.37 pts, security-triggered termination ±0.44 pts, mean delay ±0.85 ms. Profile changes per 1,000 is about ±64 (≈9%), because it follows each seed's threat path. Method gaps there are 690 vs 1,040 vs 0, so the CI does not hide them.
- Full run: 5 methods × 18 rates × 25 seeds = 2,250 simulations.

## Caveats for the figures

- Static-Strong is always q3, so its termination and profile-change counts are 0 by construction. It has no mandatory upgrades, so `sec_term_pct` has no denominator and is NaN in the CSVs; `plot_figures.py` draws it as 0, labelled "(0 by construction)".
- RASP-Profile and RASP-Reloc are identical up to about 14 req/s, because no upgrade needs relocation there.
- `mean_delay` is the delay of each admitted request at its last placement decision, averaged over admitted requests. It is not time-averaged over the session, and rejected requests are excluded, so it flattens at about 74–77 ms in overload.
- `sec_term_pct` uses admitted requests with at least one mandatory upgrade as the denominator (same as `13_final_figures` Fig. 2).
- RASP-Fog vs SA-FF is within about 1 point everywhere. SA-FF is slightly ahead on secure completion at 18–20 req/s (−0.1 to −0.2 pts paired), and RASP-Fog is ahead from 28 req/s on (+0.3 to +0.95). RASP-Fog has lower delay up to 18 req/s; from 19 req/s on the two are tied (see Step 2).

## Step 2: full run (25 seeds, 2,250 runs, 10 min on 11 cores)

```bash
python3 15_rate_figures/run_figures.py    # simulate, write CSVs, draw figures
python3 15_rate_figures/plot_figures.py   # redraw only, from rate_summary.csv
```

Outputs: `rate_raw.csv`, `rate_summary.csv` (mean and 95% CI), `rate_paired.csv` (RASP-Fog minus each method, paired by seed), and `rate_fig_secure`, `rate_fig_sec_term`, `rate_fig_delay`, `rate_fig_changes` (.pdf/.png) in the shared `../figstyle.py` style: square 3.5 × 3.5 in plots, major and minor grid, Times New Roman, framed legends inside the axes, 95% CI error bars. The secure-completion figure adds panel (b), each adaptive method's paired gain over Static-Strong, as a second square beside (a) (two-column width).

Results (paired differences are RASP-Fog minus the other method, ± 95% CI):

- **Secure completion:** 100% for every method up to 16 req/s. RASP-Fog beats Static-Strong by 1.0–1.5 pts from 20 req/s on, and RASP-Profile by 0.2–0.7 pts at 17–32 req/s. Against SA-FF it is 0.1–0.2 pts behind at 18–20 req/s, 0.3 pts ahead at 28 req/s and +0.77 to +0.95 pts ahead from 32 req/s on. RASP-Reloc (no hysteresis) is 0.1–0.4 pts ahead of RASP-Fog from 19 req/s on.
- **Security-triggered termination:** RASP-Profile (no relocation) climbs to 5–7%, against 1.6–3.7% for the methods that relocate (−3.4 to −4.0 pts paired from 22 req/s on). RASP-Fog, SA-FF and RASP-Reloc are within about 0.4 pts of each other. Static-Strong is undefined (NaN, no mandatory upgrades) and drawn as 0.
- **Mean delay:** levels off at about 74–77 ms in overload. RASP-Fog is 0.4–4.2 ms faster than SA-FF at 4–18 req/s (paired); from 19 req/s on the two are statistically tied (−0.3 to +0.2 ms, inside the CI). RASP-Fog is 1.5–5.9 ms faster than Static-Strong at every rate. RASP-Profile and RASP-Reloc are 0.9–2.6 ms faster than RASP-Fog near the knee, because they downgrade without waiting τ_H.
- **Profile changes:** about 670–680 per 1,000 for RASP-Fog and SA-FF, against 1,050–1,110 for the τ_H = 0 variants (−37%). Flat in load. Static-Strong is 0.
- **Service failure and reconfiguration cost:** `service_failure_pct` is ≤0.1% up to 16 req/s and reaches 0.8% (RASP-Fog, SA-FF), 1.0% (RASP-Reloc) and 1.9–2.1% (RASP-Profile) in overload; Static-Strong is 0. `reconfig_ms_per_req` is 1.35–1.75 ms for RASP-Fog, 1.36–1.83 ms for SA-FF and 2.1–2.65 ms for the τ_H = 0 variants; Static-Strong is 0.
- No admitted request missed its deadline at any rate (`sla_miss_pct` = 0).
